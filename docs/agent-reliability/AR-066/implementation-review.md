## Core changes

The task-local `H2AgentLiveResourceRequirement` reads the direct user goal, trusted capture/target intent and subsequently accepted user revisions through the existing goal contract. Its classification is restrictive, not a permission grant or a model-supplied locator. It distinguishes supported live references from ordinary saved-file/new-file tasks and preserves an exact captured path. The host emits the safe source constraint in the actual model request. Model/tool output cannot waive it, and Full Access does not turn a saved snapshot into the same unsaved resource.

Admission occurs before existing file grounding and dispatch. A protected live path or matching application file family cannot be passed to a generic file operation, disk Office operation (`word_paragraphs` / `check_word`), Python input or disk CAD route as a substitute. For a live browser request, plain fetch/download/extract/metadata/feed routes are not a bound tab. Unbound commands, new command jobs/stdin writes and broad file-body search are refused for live tasks. Existing job poll/cancel paths remain available. Unrelated grounded reference files and directory metadata discovery remain subject to their normal rules. Native save-copy is a separate output, not a live-input substitution.

The normalized `live_resource_required` result carries a safe explanation, preflight phase and no-effect classification. It feeds the existing Agent outcome/archive path; refusing a fallback does not mark the original task complete. The composed registry truthfully advertises that a live AutoCAD drawing provider is unsupported and a live browser-tab binding needs configuration. Closed DWG and HTTP capabilities are not described as equivalent live resources.

A transient failed native probe previously removed its last observed comparison identity. The catalog now retains that bounded owned reference only for later identity comparison when discovery is incomplete or a matching view is busy/modal/native-unavailable. It never returns that reference as a current observation. Reads and mutations still require fresh re-probing and exact document/process/view checks. Confirmed absence, ambiguity, stale identity or a replaced document retires the old session; capacity and tombstone limits remain enforced. This change does not prove recovery from the user's original real Office attach failure.

The existing host hook chain now enforces a live-source observation requirement at `BeforeCompletion`, without changing `AgentRuntimeRequest` or adding another completion engine. It delegates all existing hooks and preserves unresolved-effect diagnostics. The task-owned Office adapter records a source only after a successful selected-session operation, identity validation and final re-enumeration. Readiness/discovery alone, another application, malformed identity or an incomplete post-read native catalog cannot satisfy that source requirement. The guard throws the existing verification-required exception; the existing archive retains the resulting blocked state. No verifier pass or proof of the whole goal is manufactured. Unknown/mixed live application intent and unsupported native UIA/CAD/browser proof routes remain conservatively blocked, not silently replaced with another source.

Native post-read/post-write revalidation now also inspects discovery completeness. A still-visible candidate from an incomplete catalog is not accepted as a complete fresh observation. Before exposing a read response this is refused; after a possible write the error preserves uncertainty and requires reconciliation, never automatic replay.

## Regression design and limitations

The tests use the actual source classifier, actual `OfficeWindowCatalog`, production adapter/runtime/typed error boundary, disposable local files and durable archive. The model transport, capture validator and Office probe/client are explicitly injected fixtures. They are E1/E2 only. The positive corpus checks transient identity retention without leaking references or returning stale observations, replacement identity rejection, live-to-disk refusal, truthful readiness, unchanged source/control hashes and archive reopening without provider reallocation or mutation replay.

An optional differential test which would temporarily replace current source with old source in an isolated CI checkout was rejected by the tool safety boundary during upload. It was not uploaded, executed or retried by another route. The existing case names containing `CONTROL` identify candidate comparisons; positive execution on the new source alone is not proof of an executed old-source negative control. `old_source_control` is explicitly `NOT_RUN_TOOL_SAFETY_BLOCKED`.

The source classifier is intentionally conservative, not a complete natural-language/per-resource role resolver. The same-task trusted source-revision gap identified during review has been implemented: the existing ContractObserver inspects the entire bounded user revision sequence, including multiple queued messages. A later ordinary message cannot hide an earlier live requirement. Repeated input IDs retain the existing idempotency behavior; model proposals and retrieved tool/file text cannot become a trusted source revision. The guard is present even when the initial task was disk-only, so a later live requirement reaches both admission and completion. No second revision journal or model-text permission parser was introduced.

This revision policy is monotonic: it can restrict a task but does not silently relax a live requirement or select a different captured target. Conflicting/mixed application intent remains conservatively blocked. Per-resource mixed-source consent and approving live-to-disk equivalence inside the same task are not yet implemented; the currently supported explicit disk route is a new user task with its own source/permission context. This is a visible implementation limitation, not an environment-only test debt. The completion guard does not verify all requested edits or make unimplemented native providers available. Native CAD/browser implementations were not added. Real Office unsaved/view/selection, same-object transient reconnect and actual H2/model E3/E4 remain AWAITING_ENVIRONMENT. See `real-native-acceptance.md`.
